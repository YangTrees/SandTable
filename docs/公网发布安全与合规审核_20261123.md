## 一、结论

**当前结论：代码层有条件通过，生产部署尚未通过。**

代码中的高危鉴权后门、越权读取、分享令牌泄漏、上传伪图片、默认演示账号、未成年人 consent 缺失、公开媒体枚举等问题已完成修复，并通过隔离数据库 API 回归与真实浏览器回归。

## 五、残余风险与待办（P2，不阻塞代码合并，但阻塞公网发布）

1. **HTTPS 与反向代理未验证**：当前本地仍是 `http://127.0.0.1:8000`。生产必须由 Nginx / 网关终止 TLS，后端只监听 `127.0.0.1:8000`；强制 HSTS，禁用弱协议与弱套件。
2. **PostgreSQL 与备份未验证**：当前正式库为 SQLite。单校低并发可接受，但公网多实例必须 PostgreSQL；需完成迁移、索引、连接池、定时备份与恢复演练。SQLite 部署至少开启 WAL 与每日冷备。
3. **对象存储与上传目录未验证**：`backend/data/uploads` 为本地目录；多实例需共享存储或对象存储，并设置私有 ACL、生命周期与病毒扫描。
4. **限流与防爆破**：应用仅有账号级 5 次失败锁定；缺少 IP / 设备维度限流。反向代理需限制登录、分享访问、媒体请求频率，并配置 WAF / 防 CC。
5. **审计日志不完整**：已有审核归属，但缺少“报告查看、分享生成、分享撤销、账号删除、权限变更”的不可篡改审计流水与保留期限。
6. **数据生命周期未落地**：没有自动删除、匿名化、导出与撤回机制。需明确评估数据、沙盘图、成绩单、备份的保存期限，支持学生/监护人撤回同意后的删除流程。
7. **外部多模态模型的数据处理**：报告引擎会把沙盘图、描述、成绩等信息发送到 `MULTIMODAL_BASE_URL`。上线前必须确认供应商、数据出境/跨境、保存期限、脱敏策略与数据处理协议；如使用境外端点，需完成合规评估。不要向模型发送姓名、学号、联系方式。
8. **CSP 仍含 `unsafe-inline` / `unsafe-eval`**：前端为单文件内联脚本，ECharts 也需要 `new Function`。这降低了 XSS 防护强度。后续应拆分脚本、使用 nonce/hash，移除 `unsafe-eval`。
9. **密码与会话策略**：已有 PBKDF2、登录锁定、12 小时会话；仍建议生产启用管理员 MFA、会话主动失效、密码定期轮换与离职账号回收。
10. **未成年人合规文本**：需由法务/心理专业人员审核知情同意书、隐私政策、家长说明、报告免责声明；系统定位必须是“发展性评估参考”，不得表述为临床诊断。
11. **渗透测试与依赖扫描**：上线前至少完成一次外部渗透测试、`pip-audit` / npm 依赖漏洞扫描、CSP 与 TLS 配置扫描。
12. **PDF 与二维码未端到端验证**：本轮验证了分享数据与签名图片，但未实际扫码、未验证移动端二维码识别、PDF 导出中的字体与图片完整性。

建议按以下顺序推进：

1. 完成生产 `.env` 与 HTTPS 反向代理，先在内网以 `APP_ENV=production` 启动，确认配置校验通过。

在完成上述事项前，**不应将当前本地 SQLite 实例直接映射到公网**。
